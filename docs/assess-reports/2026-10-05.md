### HIGH — 5

**H1. Working tree dirty at assessment** — `fleet-start.config.ps1` and `pdf_mcp/server.py`
modified but uncommitted (`git status --porcelain`). The `server.py` diff is a legitimate
launcher fix (`--serve` argparse flag); it must be committed, not left to rot.
*Ref: repo-assess-and-fix.md 1A. Fixed this run.*

**H2. Hardcoded absolute backend URL in `webapp/src/lib/api.ts:1`** —
`const API_BASE = "http://127.0.0.1:11131";` used for **every** fetch (health, tools,
jobs, chat, RAG, share). It is not behind a Tauri/`__TAURI__` gate. Vite already proxies
`/api` and `/mcp` (same-origin), so the absolute URL is pure downside: a browser tab on
`http://goliath:11130` or any Tailscale MagicDNS name dies on CORS while `curl` "proves"
the backend healthy. This is the exact 2026-10-05 opencode-cli-mcp incident class.
*Ref: 1F. Canonical shape: same-origin `""` by default, absolute only when Tauri-detected.*

**H3. Webapp missing mandatory catch-them-all pages** — the app ships Dashboard,
Workbench, Pipeline, Chat, Tools, Skills, Logs. Missing: **Settings (LLM)**, **Help
page**, **Inbox**. LLM provider/model selection is crammed into the Chat controls bar
instead of a Settings page; there is no Help page. `App.tsx` has no routes for them.
*Ref: 1D / WEBAPP_SOTA_STANDARDS.md §III.*

**H4. Workbench advertises operations the batch dispatcher does not implement** —
`webapp/src/pages/Workbench.tsx` `OPERATION_MAP` exposes `metadata`→`extract_metadata`,
`fonts`→`extract_fonts`, `to-images`→`to_images`. `_run_operation()` in
`pdf_mcp/server.py` (the `/api/jobs` path the Workbench uses) handles only
`extract_text/images/tables`, `convert_markdown`, manipulate/annotate/forms/validate/rag/
intel ops. Those three operations fall through to `Unknown operation` → every click
produces a **failed job**. The underlying MCP tools do support them
(`pdf_extract(operation="metadata"|"fonts")`, `pdf_convert(operation="to_images")`), so
this is a dispatcher gap, not a missing feature. Three dead advertised buttons.
*Ref: 1D ("every advertised op works") + undeclared-fake gate.*

**H5. MCPB packaging track is not buildable** — `.mcpbignore` exists and `just mcpb-pack`
is wired to `npx @anthropic-ai/mcpb pack . dist/pdf-mcp-0.2.1.mcpb`, but there is **no
`manifest.json`**, **no `assets/prompts/{system.md,user.md,examples.json}`** (3-4-100 bar),
and **no `assets/icon.png`** (icon only exists at `src-tauri/icons/icon.png`, 512x512).
`just mcpb-pack` cannot succeed as shipped. Repo is not `.nopublish`, so the two-track
packaging standard applies.
*Ref: Phase 5 / MCPB_PACKAGING_STANDARDS.md.*

### MEDIUM — 8

**M1. Playwright e2e is not self-contained.** `webapp/playwright.config.ts` has no
`webServer`; `webapp/e2e/audit.spec.ts` navigates `http://localhost:11130` and hits
`http://127.0.0.1:11131/api/health`, so both servers must already be running. CI's
"Run Playwright e2e" step (and `just e2e`) will fail headless. The spec is also only 3
shallow smoke assertions (no page/nav walk). *Ref: 1L / 1C.*

**M2. Tauri frontend integration absent.** `src-tauri/` is a real NSIS shell
(`Cargo.toml` + `capabilities/` + `hooks.nsh` + built backend exe), but
`webapp/package.json` has no `@tauri-apps/api`, the frontend never imports
`@tauri-apps/api/event`, and nothing listens for the `backend-status` event that
`src-tauri/src/backend.rs:240` emits; there is no "Restart Backend" affordance. Health is
HTTP-polled only. *Ref: 1A / 1D.*

**M3. Backend framework: Starlette, not FastAPI.** `create_http_app()` returns
`mcp.http_app()` (Starlette) with ~22 manually-added routes — a REST-heavy surface.
`STARLETTE_NO_PYDANTIC_STANDARD.md` makes FastAPI mandatory at this route count; there is
accordingly no auto `/docs`. *Ref: 1D backend framework row.*

**M4. Dashboard has no hero / onboarding cue.** `Dashboard.tsx` opens with a bare
title + one-line subtitle + KPI grid. There is no welcome hero explaining the app, no
`data-testid="onboarding-cue"` under-hero button, and no MOCK-until-onboarded sample
state, despite `docs/ONBOARDING.md` existing. *Ref: 1D / 1P P2 / ONBOARDING_STANDARD.*

**M5. No global health/LLM bootstrap.** `healthCheck()` is only invoked by `BackendDot`,
which is rendered only on the Dashboard; `discoverLlm()` is only called on the Chat page.
Landing on `/workbench`, `/pipeline`, `/tools`, `/skills` or `/logs` leaves the status dot
stuck at "Connecting..." and the Dashboard's `llm-opportunity-banner` reads stale state
until Chat is visited. *Ref: 1D.*

**M6. Font / contrast anti-patterns.** `text-xs` used on UI labels/values across pages
(~37 hits) and low-contrast `text-zinc-(400|500)` on `bg-zinc-900/950` (~63 hits).
`text-xs` is only sanctioned inside `<pre>`. *Ref: 1P P4 / WEBAPP_SOTA_STANDARDS §III.*

**M7. Pipeline job-history is an unbounded table** (`Pipeline.tsx` `jobs.map`) with no
search, sort, filter, or pagination, and the list grows for the life of the process.
*Ref: 1D list-page ("leporello") row.*

**M8. justfile / CUA wiring drift.** The justfile (webapp present) has no
`cua-webapp-test`; the Tauri repo has no `cua-nsis-test` or `build-native` recipe despite
`scripts/just/cua-nsis-test.ps1` and `scripts/just/cua-webapp-test.ps1` existing.
`scripts/just/cua-webapp-test.ps1` calls `scripts/cua-webapp-test.py`, which **does not
exist** in `scripts/`. Also `src-tauri/build.ps1` uses `npm install` / `npx` on a
bun-locked webapp. *Ref: 1A / BUN_STANDARDS.*
